# Fifteen-minute capstone demonstration

Pre-stage a completed reviewed v2 promotion and actual evidence so CI waiting does not overrun. Keep the live workflow URL open; use real pre-recorded job evidence if approval/runtime exceeds the slot and identify its timestamp. Never bypass approval to fit the timer.

00:00–01:30 business problem: hospital admissions are duplicated, late and sensitive; morning briefing needs reliable counts.
01:30–03:00 show final rendered architecture: common synthetic source, staged micro-batches, version CDC, dbt history/Gold, monitoring, security and CI/CD, separate DEV/PROD.
03:00–05:00 working pipeline: show admission 1 winning version 2, invalid admission 2 quarantined, actual successful UUID and Silver/Gold count bridge. Explain full 24-hour evidence is separate.
05:00–07:00 observability: open all four dashboard queries and both real alert-detection records; show actual Gold lineage graph.
07:00–09:00 security proof: patient 1 administrator real synthetic values versus separate analyst MASKED/***@***/**********/NULL. Show zero-row UPDATE denial and engineer PROD denial, then recursive-role review evidence.
09:00–11:30 promotion proof: PR change V003, green tests, independent approval, merge SHA, protected production job, migration SUCCESS and SELECT RELEASE_VERSION=v2. No manual PROD model write.
11:30–13:30 results: measured before/after table and chart, credit basis or N/A, slowest baseline workload and actual 30% criterion status. If not met/unverified, state it explicitly and explain next profile-driven experiment.
13:30–15:00 runbook: detection -> investigation -> reviewed repair -> verification; summarize lessons on lateness, honest cost measurement, least privilege and CI approvals. End within 15 minutes.

Rehearsal checklist: timer result, runbook tested by a teammate, actual evidence paths, signed contribution, no secrets in screen, stakeholders' questions. Slide outline is in capstone_demo_slides.md.
