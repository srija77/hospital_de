# Operations runbook

Owner: instructor/designated on-call [fill actual name/contact]. Escalation: pipeline owner -> platform/security administrator -> mentor/business owner, using approved organization channels. No notification is sent by this repository. Capture UTC timestamps, database/role, run/query IDs, commit SHA, sanitized errors and impacted data intervals in evidence/incident_template.md. Never paste credentials or patient PII.

| Incident | Detect | Investigate | Fix | Verify recovery | Prevent recurrence |
|---|---|---|---|---|---|
| Pipeline failure | failure dashboard/ALERT_EVENTS, nonzero live command | run UUID, Snowflake query ID, warehouse status and input manifest | fix source/config in DEV; replay same immutable directory; PROD corrections through approved PR | new SUCCESS UUID, counts and freshness, no lost batch | add validation and alert regression case |
| Stale data | freshness age > configured minutes or no successful load | last success, producer checkpoint, COPY history, auth/warehouse and dbt run | resume source, replay missing files, successful load/build; never advance marker without success | actual last load advances and detected_status FRESH | schedule ownership, host uptime and alert review |
| Failed dbt tests | build nonzero/run_results.json | failing model/test rows and upstream quarantine/contracts | correct model/source in DEV, run build, promote PR | build/tests zero failures, all-column reconciliation | add business case and update test catalog |
| Duplicate/late events | Bronze/Silver differences, version history | event_id, version/time, source payload, quarantine reason | retain raw; rerun version MERGE; do not delete history to force counts | one admission key, newest version, explicit count bridge | stable source IDs and precedence contract |
| Reprocess/backfill | missing range or corrected source | retained files, cutoff, source-effective patient versions, expected scope | DEV replay retained immutable files; if COPY history expired avoid FORCE unless intentional Bronze replay documented; PROD through reviewed migration/job | bidirectional reconciliation, Gold key integrity and freshness | retention and backfill rehearsal |
| Deployment failure | GitHub job nonzero/STARTED migration | commit, migration checksum/history, dbt artifact, policy attachments | pause promotion; fix idempotent migration in new version or rerun unchanged interrupted one after review; protect service key | DEV succeeds, authorized PROD completes and security assertions pass | required checks and concurrent-run restriction |
| Rollback | new release fails business/security acceptance | identify last known-good commit and dependent migrations | revert model code in new PR; append corrective SQL migration; retain history; no manual PROD data edit | known-good marker/model, tests/reconciliation/masks and permissions | backward-compatible migrations and rollback drill |
| Permission error | insufficient privileges/error codes | active/secondary roles, recursive role grants, PUBLIC, object owner and target DB | security admin grants minimum intended privilege through reviewed grants; no broad admin shortcut | allowed/denied test matrix with distinct identities | periodic grants review and separate keys |
| Credential rotation | expiration, compromise alert or scheduled rotation | identify affected service and recent usage without exposing key | generate new pair outside repo, admin updates public-key slot, update environment secret, test, retire old key | workflow auth successful; old key invalid and no leaks | rotation owner/calendar and environment-scoped credentials |
| Incident escalation/evidence | customer impact, repeated failures or security exposure | impact window, affected layers, counts, masked records and current release | notify designated owner using approved channel, preserve evidence, contain access as authorized, promote fix | owner signs off restored service and retained sanitized evidence | post-incident action owner and follow-up test |

Detailed replay: preserve checkpoint and content hashes; run DEV load on the affected batch; re-MERGE rescans Bronze and older versions cannot overwrite newer ones; run dbt build so late patient corrections reassign historical fact keys. Check both directions against the relevant expected batch snapshot, not blindly the initial demo baseline after new source data arrives.

For native ingestion, preserve stream_state.json, commits.jsonl, source JSONL/manifest, named-channel identity and server offset. Restart hospital.streaming with the same source/output; never repair by resetting offsets or deleting the pipe/channel. A server-behind checkpoint or rejected-row count requires investigation. Silver task failures roll back cursor consumption with the MERGE; repair and retry through the documented DEV process. Suspend the task and stop the Gold refresh loop before intentional dataset reset or benchmark experiments. Native streaming currently targets DEV only.

Security rollback: do not drop masking policies while analysts retain SELECT. Disable downstream access via authorized security procedure if necessary and promote the corrected model/policy path. Existing dim_patients policies survive incremental MERGE. Never disable policy hooks to obtain a green build.

Warehouse rollback: benchmark runner restores original size and drops only its experimental copy. If force-terminated, authorized DEV owner verifies original size from captured SHOW WAREHOUSES evidence and restores it; account owner reviews cost. PROD warehouses are not experiment targets.

Teammate drill: a teammate who did not author this runbook must execute a controlled DEV failure, stale recovery and additive rollback rehearsal. Record their name, incident/query IDs, steps that were unclear and verification sign-off. This human acceptance criterion remains pending until performed.
